# docs/hark — Hark 的规格与交互模拟器（参考资料）

这个目录只放 **Hark 写的设计资料**，不放可运行代码，不改动 `firmware/`、`host/`、根目录 `index.html`。框架由另一个 agent 负责。

## 当前定稿方向（2026-10-22，以用户最新口径为准）

整合后只有 **3 个功能**，对应框架里的三种模式：

1. **遥控（核心）**：获取封面、播放/暂停、调音量等媒体控制。
2. **PTT（Push-to-Talk）**：按住说话、松开发送。
3. **Standby（待机）**：语音互动宠物。

## UI 视觉基线（2026-10-23 用户确认）

根目录 `index.html`（Wabi 做的「圆屏遥控器 · Tokyo Night · 本地预览 v6」）是 **当前认可的 UI**：Tokyo Night 配色、中心封面、顶部来源键（音乐/播客/视频）、外环音量、底部弧线进度、6 格桌面视图。
固件 UI 以它为准还原；本目录的 `simulator.html` 只作交互/手势参考，视觉以 v6 为准。

## 尚未定的：操作逻辑

手势/交互方案 **还没定**，用户要先看屏幕实际触控反馈再决定（例如"上下滑调音量"只是候选）。
本目录里 spec 和模拟器中的手势、页面结构都是 **草案**，不要据此在固件里写死交互；交互层应能整体替换。

## 用户的硬性要求：模块化

- 改动一个模块，不能牵一发而动全身。
- 三个模块之间不直接互相调用，只通过 `mode_router` 和各自的事件/生命周期接口交互（与 `docs/architecture.md` 一致）。
- 交互/手势层、UI 皮肤、通信协议各自独立；换手势方案不应改到遥控、PTT、宠物的业务逻辑。
